# AI質問機能 設計書

採用済みの [要件定義書](requirements.md) に基づく。TOP、TODO v1、TODO v2 に AI 質問画面へのリンクを追加する。AI 質問画面は既存の EJS 構成に合わせて `/ai` の専用ページとする。

## DES-AI-001 構成と処理の流れ

| 構成要素 | 役割 |
|---|---|
| ブラウザ | 同一オリジンの Express に質問・履歴を要求し、待機、成功、空状態、失敗を表示する。 |
| Express | 画面を配信し、デモの可否と入力を検証する。Gemini から回答を取得し、保存した結果を返す。 |
| Gemini API | 今回の質問から回答を生成する。過去の履歴は送信しない。 |
| PostgreSQL | 質問、回答、作成日時を1行に保存し、最新の履歴を返す。既存の `db.ts` の接続プールを共有する。 |

質問はブラウザ → Express → Gemini → Express → DB の順に処理し、保存された行を Express からブラウザへ返す。履歴取得は Express と DB の間で完結する。

## DES-AI-003 画面と状態

画面には、質問入力欄、送信ボタン、回答欄、履歴一覧、履歴更新ボタン、状態・エラーの通知欄、TOP・TODO への戻りリンクを置く。質問と回答は改行を保持して表示する。待機や結果の通知は読み上げ可能にする。

| 状態 | 表示と操作 |
|---|---|
| 初期取得 | 履歴を1回取得して読み込み中と表示する。取得完了まで送信と履歴更新を無効にし、初期取得が失敗しても両操作を再度使えるようにする。 |
| 送信待機 | 画面遷移なしで送信し、待機表示中は送信と履歴更新を無効にする。送信処理の開始済み状態でも二重操作を防ぐ。 |
| 成功 | `201` の項目から保存済みの回答を表示し、質問欄をクリアする。履歴APIを1回取得し、DBが返した最新20件以内の一覧で置き換える。履歴の更新だけが失敗した場合は、回答と保存成功の表示および取得済みの一覧を保持し、履歴更新の失敗を別に案内する。 |
| 履歴0件 | 「履歴はまだありません」と表示する。 |
| 失敗 | DES-AI-004 の原因別案内を出す。送信失敗時は質問を保持し、今回の成功表示は出さない。履歴取得失敗時は取得失敗を案内し、表示済み履歴があれば保持する。 |
| 待機終了 | 送信成功後の履歴更新も待機期限の対象とし、その取得が終了するまで送信と履歴更新のボタンを無効にする。成功・失敗・タイムアウトいずれでも待機表示を解除し、画面操作による再送・履歴更新を受け付ける。 |

## DES-AI-004 API契約

API の応答は JSON とし、質問・回答を含む応答に `Cache-Control: no-store` を付ける。

| URL | 入力 | 成功応答 |
|---|---|---|
| `POST /api/ai/ask` | `Content-Type: application/json`。JSONオブジェクトの `prompt` はNUL（U+0000）を含まない文字列。前後の空白を除去して1〜2,000 Unicodeコードポイント。本文は16,384バイト以下。 | `201`、`{ "success": true, "item": { "id": 1, "prompt": "質問", "responseText": "回答", "createdAt": "2026-01-01T00:00:00.000Z" } }` |
| `GET /api/ai/history` | リクエスト本文・検索条件は不要。 | `200`、`{ "success": true, "items": [...] }`。項目の形式は `item` と同じ。最大20件で、0件なら空配列。 |

失敗応答は `{ "success": false, "error": { "code": "...", "message": "..." } }`。画面は既知のコードに応じた固定案内を使う。

| HTTP | コード | 条件と画面の案内 |
|---|---|---|
| 400 | `BAD_REQUEST` | JSON形式・型の不正、質問なし、NULを含む質問、JSON以外のメディアタイプ。入力または送信形式を確認する。 |
| 404 | `NOT_FOUND` | デモ有効時のAI配下に未登録のURLまたはメソッド。 |
| 413 | `BODY_TOO_LARGE` | JSON本文が16,384バイトを超過。送信内容が大きすぎると伝える。 |
| 422 | `INVALID_PROMPT_LENGTH` | 空白除去後の長さが範囲外。入力範囲を案内する。 |
| 502 | `AI_UNAVAILABLE` | 上流通信・応答の失敗、利用可能な回答本文がない場合。AI回答を取得できなかったと案内する。 |
| 504 | `AI_TIMEOUT` | サーバー側の AI 待機期限超過。AI回答を取得できなかったと案内する。 |
| 500 | `SAVE_FAILED` | DBが書き込みを拒否したなど、保存に失敗したと確定できる場合。回答を保存できなかったと案内する。 |
| 500 | `SAVE_RESULT_UNKNOWN` | SQL送信後の接続断などで書き込みの成否を確認できない場合。結果未確認と伝え、自動再送せず、利用者に履歴の更新を案内する。 |
| 500 | `HISTORY_FAILED` | DBから履歴を取得できない。履歴取得の失敗を案内する。 |
| 500 | `INTERNAL_ERROR` | AIのサーバー設定不足またはその他の処理例外。現在処理できないと案内する。 |
| 503 | `DEMO_DISABLED` | デモ無効・未設定、または Production。デモ停止を案内する。 |

未知のコード、非JSON、通信エラーは該当する要求の失敗として扱い、通信または応答の問題を案内する。ブラウザ側で質問のPOSTが期限超過した場合は保存結果未確認、履歴のGETが期限超過した場合は履歴取得失敗と表示する。質問の `201` を受け取った後は、履歴取得が失敗しても回答と保存成功の表示を維持する。

## DES-AI-005 データとSQL

`id` は一意な整数、`prompt` は正規化した質問、`response_text` は回答の原文、`created_at` はDBが付与する作成時刻。時刻はAPIでUTCのISO 8601形式に変換する。利用者IDを持たないため、同じ環境の履歴は許可された利用者間で共有される。

質問成功時の `item` と履歴取得時の `items` の各要素には、同じ変換を適用する。

| DB列 | API項目 |
|---|---|
| `id` | `id` |
| `prompt` | `prompt` |
| `response_text` | `responseText` |
| `created_at` | `createdAt` |

```sql
CREATE TABLE ai_qa_logs (
    id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    prompt text NOT NULL CHECK (char_length(prompt) BETWEEN 1 AND 2000),
    response_text text NOT NULL CHECK (response_text ~ '[^[:space:]]'),
    created_at timestamptz NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX ai_qa_logs_history_idx
    ON ai_qa_logs (created_at DESC, id DESC);
```

質問の前後空白除去と回答の空白判定はアプリでも行う。PostgreSQLの `text` が扱えないNULを含む質問は、Controllerの入力検証で拒否し、Geminiを呼び出さない。保存は1回の `INSERT` で完了し、`RETURNING` の結果から成功応答を作る。

```sql
INSERT INTO ai_qa_logs (prompt, response_text)
VALUES ($1, $2)
RETURNING id, prompt, response_text, created_at;

SELECT id, prompt, response_text, created_at
FROM ai_qa_logs
ORDER BY created_at DESC, id DESC
LIMIT 20;
```

## DES-AI-006 ルート登録順と例外処理

1. `index.ts` で `/api/ai` を共通の `express.urlencoded()` と静的配信より前に登録する。AI API の処理はその配下で完結させる。
2. AI API 内ではデモ判定を最初に行う。停止中は両エンドポイントで `503` を返すため、不正な本文も解析せず、Gemini 呼び出しとDB操作も行わない。
3. デモ有効時は質問の `POST` だけでメディアタイプを確認し、上限16,384バイトのJSON解析を行ってから Controller で検証する。履歴の `GET` に本文パーサーを付けない。
4. AI の未定義ルートは `404` と固定のJSONエラー `NOT_FOUND` を返す。AI 専用の例外ハンドラーをルーター末尾に登録し、パーサーや Controller の例外を固定応答へ変換する。ヘッダー送信済みの例外は Express へ委ねる。
5. 共通フォーム解析、静的配信、TOP、DBサンプル、DB接続確認、TODO v1/v2 の登録は現在の相対順を維持する。`GET /ai` で EJS を描画する。AI API 配下以外の未定義URLは既存の Express 標準404を使う。TODO v1/v2 のJSON解析と例外処理は既存ルーター内に残す。

要望書のグローバルエラー処理については、既存応答への影響を避けるため AI 専用ハンドラーを設計案とし、API設計レビューで講師の採否を確認する。

## DES-AI-007 秘密情報と表示・ログの安全対策

- `GEMINI_API_KEY`、`GEMINI_MODEL`、`AI_DEMO_ENABLED` はサーバー環境変数で管理する。DBは既存の `DATABASE_URL` を使用する。ローカルは既存の dotenv 読み込みを再利用し、Gemini 設定の検証は質問処理時に行う。AI の未設定で TOP・TODO の起動を妨げない。
- 質問・回答・エラーメッセージはブラウザでテキストとして挿入する。HTML として評価しない。SQL の質問と回答はプレースホルダーにバインドする。
- AI のログは処理種別、結果コード、所要時間に限定する。質問、回答、キー、接続文字列、リクエスト本文、SDK例外オブジェクトは出力しない。利用者にも固定メッセージだけを返す。

## DES-AI-008 待機期限と部分成功

- サーバーから Gemini への待機期限は30秒、ブラウザでの待機期限は各POST・GETにつき45秒を参考値とする。DB待機とホスティングの実行期限も含めて実環境で確認し、ブラウザがサーバーのエラーを受け取れる余裕を検証する。
- ブラウザは自動再送をせず、SDK は初回の1回だけ送信する設定を使う。SDK選定後に、期限で中断できることと上流への送信回数を検証する。期限超過後に遅れて到着したAI回答を保存しない。
- 回答取得の失敗では保存しない。保存が成功したと確認できるまで `201` を返さない。保存失敗が確定したら `SAVE_FAILED`、書き込みの成否が不明なら `SAVE_RESULT_UNKNOWN` を返す。ブラウザ側のタイムアウトはDES-AI-004のとおり要求ごとに扱い、画面から履歴を手動で更新できる。同じ質問を手動で再送すると別の行になり得る。

## DES-AI-009 PreviewとProductionの運用

1. Preview と Production では最初に `AI_DEMO_ENABLED` を無効化する。明示値 `true` の場合だけ有効とし、Production では設定にかかわらず停止する。Vercel の Production 判定には `VERCEL_ENV` を使い、実環境で設定を確認する。
2. Preview のアクセス保護を設定し、未認証のブラウザで `/ai` と両APIへの直接アクセスが遮断されることを確認する。
3. 保護済み Preview を有効にして再デプロイし、有効化後の同じデプロイで未認証時の遮断と、許可された利用者による質問・履歴取得を確認する。保護できない場合はローカルで実演する。
4. Production で両APIの `503` と、TOP・TODOの正常動作を確認する。保存期間・削除日・担当は実データを保存する前に講師が確認する。

Gemini のモデルID、SDK・依存ライブラリのバージョンは未確定。講師の指定と利用環境での動作確認後に確定する。
