# AI質問機能 要件定義案

## 背景・目的・対象範囲

既存の Express／TypeScript アプリに、利用者が質問を入力し、AI の回答を画面で確認できる機能を追加する。対象利用者は既存アプリの一般利用者と管理者。授業での実行デモはローカル環境またはアクセス保護済みの Preview に限定する。

標準課題は質問・回答表示、質問と回答の保存、履歴表示、失敗時の案内、公開停止、既存機能の維持までとする。ログイン、会話記憶、Markdown 表示は標準範囲外とし、発展課題としての採用は未決定とする。

根拠は [要望書](request.md) と授業テキストの「5.2 授業で合わせる共通条件」。画面配置やライブラリ選定は後続工程で決める。

## 機能要件

| 要件ID | 満たす条件 | 受入条件 |
|---|---|---|
| REQ-AI-F001 | 質問を入力・送信でき、回答を同じ画面で読める。処理中は待機状態を表示し、重複送信を防ぐ。 | 有効な質問を送ると画面遷移なしで回答が表示される。待機中に送信を繰り返しても質問のPOSTは1回で、処理終了後は再操作できる。 |
| REQ-AI-F002 | 質問はNUL（U+0000）を含まない文字列とし、前後の空白を除いて1〜2,000 Unicodeコードポイントを許容する。JSON本文の受信上限は16 KiB（16,384バイト）とする。 | 空白のみ・文字列以外・NULを含む質問・2,001コードポイント・不正JSON・上限超過を拒否し、AI呼び出しと保存を行わない。有効な1・2,000コードポイントの質問と上限ちょうどの有効なJSONを受理する。補助平面の文字も1コードポイントと数える。 |
| REQ-AI-F003 | サーバーから Gemini API に今回の質問だけを送る。回答取得とDB保存の両方が完了した場合に限り、質問の成功を返す。 | 上流への送信内容に履歴が含まれない。回答取得と保存が完了すると `201` を返す。回答取得が失敗した場合は保存せず、保存失敗時は成功を返さない。 |
| REQ-AI-F004 | 保存済み履歴の最新20件を表示する。0件は正常として扱う。 | 履歴取得は `200` を返し、0件なら `items: []` と空状態の案内を表示する。21件以上ある場合は REQ-AI-D002 の順序で20件を返し、再読み込み後も確認できる。DB障害時は失敗を表示する。 |
| REQ-AI-F005 | 入力不正、AI通信失敗・タイムアウト、DB障害、予期しない応答を下表のとおり扱う。待機状態を解除し、ブラウザとSDKの自動再試行を行わない。 | 各失敗を模擬すると下表の案内を表示し、利用者が再操作できる。失敗した送信の成功表示は出ず、追加の要求やAI呼び出しが自動で発生しない。サーバー側で例外が起きた後も、同じプロセスが次の正常な要求に応答する。 |
| REQ-AI-F006 | デモが無効または未設定の場合、質問・履歴APIを停止する。標準課題の Production では両APIを停止する。 | 無効・未設定および標準課題の Production では両APIが `503`・`DEMO_DISABLED` を返し、AI呼び出しやDBアクセスが発生しない。不正JSONを送っても停止応答が優先され、TOP・TODOは利用できる。 |

### 失敗時と履歴0件の受入条件

| 対象ID | 状況 | 期待するAPI応答 | 画面で確認すること |
|---|---|---|---|
| REQ-AI-F002 | 質問の欠落・型不正・NULを含む質問・不正JSON | `400`。AI呼び出しと保存は発生しない。 | 入力または送信形式を確認するよう案内する。 |
| REQ-AI-F002 | 空白のみ・質問長の超過 | `422`。AI呼び出しと保存は発生しない。 | 質問の入力範囲を案内する。 |
| REQ-AI-F002 | JSON本文のサイズ超過 | `413`。AI呼び出しと保存は発生しない。 | 送信内容が大きすぎることを案内する。 |
| REQ-AI-F003、REQ-AI-F005 | AI通信失敗・サーバー側のAI待機期限超過 | 通信失敗は `502`、期限超過は `504`。保存は発生しない。 | AI回答を取得できなかったことを案内する。 |
| REQ-AI-F003、REQ-AI-F005 | AI回答取得後の保存失敗 | `500`。成功結果は返さない。 | 回答を保存できなかったことを案内する。 |
| REQ-AI-F003、REQ-AI-F005 | AI回答取得後にDB書き込みの成否を確認できない | `500`。成功結果は返さず、保存失敗が確定した場合と区別する。 | 保存結果が未確認であることを案内する。自動再送せず、利用者が履歴を更新できるようにする。 |
| REQ-AI-F004 | 履歴0件 | `200`、`items: []`。 | 履歴がまだないことを表示する。 |
| REQ-AI-F004、REQ-AI-F005 | 履歴取得時のDB障害 | `500`。成功の空配列は返さない。 | 履歴を取得できなかったことを案内する。 |
| REQ-AI-F005 | ブラウザ側の送信待機期限超過 | ブラウザ側では応答結果を確認できない。 | 結果未確認と案内する。自動再送せず、保存済みの結果は履歴の再取得で表示する。 |
| REQ-AI-F004、REQ-AI-F005 | ブラウザ側の履歴取得の待機期限超過 | ブラウザ側では履歴応答を確認できない。 | 履歴取得の失敗を案内する。質問の `201` を受け取っていれば、回答と保存成功の表示を維持する。 |
| REQ-AI-F005 | ブラウザ側の通信失敗・非JSON応答 | 利用できるAPI応答を取得できない。 | 通信または応答の問題を案内し、成功表示を出さない。 |

## 非機能要件

| 要件ID | 満たす条件 | 受入条件 |
|---|---|---|
| REQ-AI-N001 | APIキーなどの秘密情報はソースへ直書きせず、サーバーの環境変数で管理する。ローカルでの環境変数の読み込みには要望書の指定に従い dotenv を使う。利用者へのエラー応答には秘密情報や内部例外の詳細を含めない。 | ソース全体と配信ファイルをレビューし、秘密値の直書きがなく、サーバーが環境変数から設定を取得することを確認する。ブラウザの通信、エラー応答、提出差分に秘密値が含まれず、ブラウザから Gemini への直接通信がない。 |
| REQ-AI-N002 | 既存TODOと同様に、ルーティング、リクエスト処理、AI通信、データアクセスの責務を分け、既存のTOP・TODO・DB接続・404・エラー処理を維持する。 | 責務の分離をレビューし、TOP、TODO v1/v2、DB接続確認、未定義URL、既存TODOの入力エラーを追加前の挙動と照合できる。 |
| REQ-AI-N003 | 質問と回答をプレーンテキストとして安全に表示する。 | タグやスクリプトを含む質問・回答を送信結果と履歴で確認すると、文字列として表示され、実行されない。 |
| REQ-AI-N004 | 実行デモはローカル、またはアクセス保護を確認済みの Preview でのみ有効化する。 | Preview の有効化前に、未認証のブラウザから画面と両APIへの直接アクセスが遮断されることを確認する。有効化後の同じ Preview デプロイで遮断を再確認し、許可された利用者は質問と履歴を利用できることを確認する。保護を確認できない場合はローカルで実演する。 |

## データ要件

| 要件ID | 満たす条件 | 受入条件 |
|---|---|---|
| REQ-AI-D001 | 保存する1件は識別子、正規化した質問、AI回答、作成日時を持つ。質問と回答を組として保存する。 | 正常送信後に4項目を持つ1件を履歴から確認できる。AI回答の取得に失敗した要求は履歴に現れず、保存失敗でも質問や回答だけのレコードが残らない。 |
| REQ-AI-D002 | 履歴を作成日時の降順、同日時なら識別子の降順で取得する。 | 作成日時が異なる行と同日時の行を用意し、最新20件が指定順で毎回返ることを確認できる。 |
