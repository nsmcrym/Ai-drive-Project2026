# TODOアプリ V2 要件定義

## 1 目的と対象範囲

優先度付きのTODOを作成し、完了状態と優先度で絞り込めるようにする。V2は `/todo-v2` に画面を置き、Fetchを使う `TodoApiV2` から `/api/v2/todos` を操作する。

V1の `/todo`、`/api/v1/todos`、`TodoApi`、応答形式を維持する。V1の `todo_tasks` とV2の `v2_todo_tasks` は別のテーブルとし、V1のデータの削除・初期化・自動移行は行わない。既存のDB接続と `DATABASE_URL` を使い、確認には架空のデータを使う。

## 2 機能と受け入れ条件

| 要件 | APIと画面操作 | 受け入れ条件と確認方法 |
| --- | --- | --- |
| V2-REQ-01 一覧と絞り込み | `GET /api/v2/todos`。画面で完了状態と優先度を選び、クエリ `completed` と `priority` で指定する | 条件なしではV2の全件を返す。各条件を単独で指定すると一致する行だけを返し、両方を指定すると両方に一致する行だけを返す。対象なしでも `200` と `data: []`。APIと画面の表示を照合する |
| V2-REQ-02 登録 | `POST /api/v2/todos`。画面から `title` と任意の `priority` を送る | `201` で登録済みTODOを返し、再取得して優先度が保存されていることを確認する。省略時は `normal`、初期状態は未完了 |
| V2-REQ-03 部分更新 | `PATCH /api/v2/todos/:id`。画面から完了状態または優先度を変更する | 真偽値の `isCompleted` と、許可された `priority` のうち、渡された項目だけを更新し、`200` で更新後のTODOを返す。各項目単独と両方を送る場合を確認し、タイトルが変わらないことを確かめる |
| V2-REQ-04 削除 | `DELETE /api/v2/todos/:id`。画面から対象を削除する | `204` で本文なし。再取得した一覧から消える。同じIDの再削除は `404` になる |

## 3 データとエラー条件

優先度は `low`、`normal`、`high` のいずれかとする。V2の成功JSONはV1の形式に合わせ、TODOに `priority` を追加する。`title` は前後の空白を除いて1〜100文字、パスのIDは1以上の整数とする。`completed` クエリで受け付ける値は `true` と `false`。PATCHでは少なくとも1つの更新項目を受け付ける。

不正なJSON、必須項目の欠落、型違い、形式が不正なIDや `completed` は `400`。タイトルの長さ違反や許可されていない優先度の値は `422`。存在しない有効なIDは `404`。サーバー内部エラーとDB接続不可は既存仕様に合わせて `500` と `503` とする。エラーJSONはV1と同じ `status`、`code`、`message`、`details` で返す。

## 4 互換性と環境別確認

Neon SQL Editorで `sql/todo/021_create_todo_tasks_v2.sql` を手動実行する。対象ブランチ・DB、実行日、結果を `sql/README.md` に記録する。

ローカルとVercel Previewで、V2の正常系、不正な優先度・完了状態、存在しないIDを確認する。V1でも4つのAPIと画面を再確認する。V2の登録や更新がV1の一覧に影響しないことを確認し、結果を `docs/todo/v2/04_test_results_v2.md` に記録する。PRをマージした場合はProductionでも両方を確認する。
